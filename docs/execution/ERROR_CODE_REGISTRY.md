# Error Code Registry

Stable codes are machine-readable behavior; localized messages are not. New
code must be added at the owning boundary and tested before it is documented
here. Do not reuse a code for a different condition. The linked source remains
the executable authority.

## Stable warning codes

Warnings are accepted business results or review signals, not errors:

| Codes | Meaning/source |
|---|---|
| `AUTHORIZATION_STALE_EXCEPTION`, `LATE_SHIFT_EVENT` | Accepted durable offline event requires authorization/closed-Shift review; [`apps/api/src/cash.ts`](../../apps/api/src/cash.ts), [`apps/api/src/sales.ts`](../../apps/api/src/sales.ts). |
| `STALE_PRICING_EXCEPTION`, `COST_MISSING_EXCEPTION` | Sale accepted with pricing/cost review; [`apps/api/src/sales.ts`](../../apps/api/src/sales.ts). |
| `SHORT_DELIVERY`, `OVER_DELIVERY`, `BONUS_VARIANCE`, `DUPLICATE_SUPPLIER_INVOICE_REVIEW`, `NEGATIVE_STOCK_RECONCILIATION_INCOMPLETE` | Purchasing/Costing review signals; [`apps/api/src/purchasing.ts`](../../apps/api/src/purchasing.ts). |
| `OPNAME_RECOUNT_RECOMMENDED` | Movement watermark changed after a physical count; [`apps/api/src/inventory.ts`](../../apps/api/src/inventory.ts). |
| `REFUND_PROVIDER_PENDING` | Return completed while Refund remains operationally pending; [`apps/api/src/returns.ts`](../../apps/api/src/returns.ts). |
| `CLOCK_UNTRUSTED` | Offline resolver used a fail-safe clock path; [`packages/domain/src/pricing/resolver.ts`](../../packages/domain/src/pricing/resolver.ts). |

Sync result statuses such as `ACCEPTED`, `ACCEPTED_WITH_REVIEW`,
`REJECTED_VALIDATION`, or `REJECTED_CONFLICT` are protocol dispositions, not
error codes, and remain defined by the sync contract/source.
